# The grasp pipeline, every detail

Everything below is what the code in this folder does (`ros2_iface/grasp_node.py`, `arm.py`, `housing_grasp/color_marker.py`, `config/grasp.yaml`). Items marked **[verified]** were run on the real arm or checked on real data; **[offline]** = checked only on saved data / synthetic tests; **[not run]** = never executed. Last updated 2026-11-07.

## 0. In one page
```
home -> SCAN 7 recorded joint poses (colour + depth) -> merge, ICP, voxel -> COLOUR MARKER coarse target (table RANSAC, DBSCAN, marker cluster centroid)
     -> VIEW camera 18 cm over that point -> GRASP COMPUTATION (one of 3 modes) -> EXECUTE (IK check, open, descend, close, lift, hold check)
```
| switch | values | where |
|---|---|---|
| grasp mode | `head` (default) / `cloud` / `model` (STEP model + panel tag; needs `config/panel_map.yaml` measured) / `cad` (STEP model fitted to 3 close views, `config/connectors.yaml`); the sticker mode is archived | `run_pipeline.py --mode ...`, node param `grasp_mode:=...` for `/grasp/pick` |
| candidate search (CLOUD mode only; the head mode always runs its grid search, no switch) | on / off | `color_marker.candidate_search` in the config, or node param `candidate_search:=on|off|config` (restart the node to change) |
| which side faces the pads touch (cloud mode) | `edge_prior` / `larger` / `smaller` | `color_marker.contact_faces` |
| where those sizes come from (cloud mode) | `sticker` (marker only) / `footprint` (dark + marker outline) | `color_marker.extent_source` |
| which sticker edge the jaws follow (`edge_prior`) | `long` / `short` | `color_marker.jaw_edge` |
| motion | dry run / real | node param `dry_run` (default true; `run_ros.sh dry_run:=false`) AND `/grasp/allow_grasp` for `execute` |

## 0b. The marker colour is a setting, not a rule
The pipeline needs a sticker of ONE distinct colour on the head's top face; it is found by thresholding in the image (`color_marker.h`, `s_min`, `v_min`, OpenCV HSV). It is teal today; any colour works once its range is set. Everything else is named `marker_*` / `color_marker` / `color_target` / `sticker_*` on purpose.
- Hue is 0-179. A colour that wraps past 179 (red) is written with the first number larger: `h: [170, 10]`.
- Measure it once on a saved frame (e.g. a `frame.npz` / `view_XX.npz`, colour is BGR; frames saved by the node are BGR, an old `frame.npz` from before 2026-11-07 is RGB): `python3 -c "import numpy as np, cv2; f=np.load('FRAME.npz'); h=cv2.cvtColor(f['color'][y0:y1, x0:x1], cv2.COLOR_BGR2HSV).reshape(-1,3); print(np.percentile(h, [5,50,95], axis=0))"`, then set `h` to about median hue +-10, `s_min` below the 5th percentile of S, `v_min` below the 5th percentile of V. The wood table is H 12-16 / S ~90, white parts are S < 90, so a saturated colour keeps them out.
- The dark-body outline used by the `sticker` mode and `extent_source: footprint` assumes a DARK housing (`color_marker.dark_v`); the `cloud` mode does not use it.

## 1. Hardware layer (`robot_ros.py`, `arm.py`)
- Joint states `/joint_states`, TF `base_link -> tool_frame`, camera topics `/camera/camera/color/image_raw`, `aligned_depth_to_color/image_raw`, `camera_info`.
- MoveIt (`move_group`) is only asked two things: `/compute_ik` (`avoid_collisions: false`) and `/compute_cartesian_path` (`avoid_collisions: false`, 5 mm steps). Its execution is NOT used (the stock config names the controller `gen3_lite_joint_trajectory_controller`, the driver runs `joint_trajectory_controller`).
- Trajectories go to `/joint_trajectory_controller/follow_joint_trajectory`: joint moves are quintic from the current joints to the target (duration max(2 s, largest joint move / `motion.joint_speed_deg_s` 10 deg/s)); straight lines are the MoveIt waypoints re-timed at `motion.line_speed_mps` 0.04 m/s (min 2 s). Gripper: `/gen3_lite_2f_gripper_controller/gripper_cmd`.
- Guards in `arm.py`: IK must be within `max_dev_deg` of its seed for every joint (no wrist flips); a pose whose TCP z is below `scan.table_z_m - 5 mm` (-46 mm) is refused; one 5 mm line step may not move a joint more than 0.1 rad.
- Not present (switched off or never built): collision checking of the arm/fingers against the scene (only the table floor above), a side approach.

**Run start (all modes, `run_pipeline.py`)**: arm within 1 deg of `scan.home_joints_deg` or `/grasp/home` first, then checked within 2 deg (else the run stops, e.g. in a dry run); gripper `/grasp/open_gripper` (opens fully if its position is above 0.05 rad).

**Motion (all modes, since 2026-11-18)**: every joint move and straight line is a quintic profile (`housing_grasp/motion_profile.py`): zero speed and acceleration at both ends, continuous in between; the controller gets positions, velocities AND accelerations on every point (quintic spline interpolation; before, joint moves had no accelerations and straight lines had no velocities, so they started and stopped with a speed step). `motion.joint_speed_deg_s` 25 (was 10, min move 1 s instead of 2 s), peak joint speed capped at `max_joint_vel_deg_s` 60, lines 0.05 m/s average (min 1.5 s) and they arrive at the grasp point at rest. Offline numbers: 80 deg move 3.2 s (was 8 s). Not yet run on the arm.

**Registration finding (2026-11-18, 9 real 7-pose scans + 2 longer ones)**: the same sticker seen from the 7 views is up to 19 mm apart with the kinematics + hand-eye alone (height spread 5.5 mm). Our trimmed ICP makes it WORSE (25 mm; shifts of 10 mm median / 30 mm max): a flat table lets ICP see only height and tilt, the in-plane shift and yaw drift. Levelling each view's table plane onto the consensus is also worse (27 mm); fitting a hand-eye + depth-scale correction from the table planes alone is degenerate (gave -37% depth scale). So `scan.icp` is OFF by default (views are stacked as the kinematics place them). Root cause = calibration: needs a non-planar target (`Code/Calibration/hand_eye_calibration.py`, ArUco, never run on the arm). The CAD mode only uses local geometry around the connector, which is why it is less affected.

## 2. Scan (`/grasp/scan`) [verified]
1. Poses: `scan.views_joints_deg` = 7 joint poses (6 angles each, deg) recorded by hand on 2026-11-10 from the Kinova Web App monitoring page (screenshots in `insertion_task/source/`). They are visited as they are, with NO IK. All 7 are tilted views (camera axis 30-71 deg from straight down) that see the head 0.20-0.29 m away. Order = least joint travel (474 deg in total, 89 deg the largest move, about 47 s of motion at `motion.joint_speed_deg_s`). `tools/check_scan_poses.py` re-checks any new pose list offline: forward kinematics from the robot URDF (matches the 7 screenshot tool positions to 0.3-0.7 mm), lowest point of the straight joint-space path home -> poses -> home (fingertip >= 57 mm above the base plane, table at -41 mm), and whether each pose sees the head. (The older mode, `scan.views` as Cartesian `[x, y, height, tilt, yaw]` + IK, still runs if `views_joints_deg` is absent; its list is in git.)
2. Nothing is skipped for IK; joint moves go straight to the controller (no collision checking: the path check above is the only one).
3. Joint move, wait 0.7 s, capture `scan.frames_per_view` (3) depth frames (median, zeros ignored) + the latest colour frame; `T_BC = T_base_tool x hand-eye`. Saved as `Media/Grasp/work/scans/<ts>/view_XX.npz` (depth, color, K, T_BC, T_BT). After the last view the arm returns to the start pose.
4. Per-view cloud: all valid pixels, 3x3 depth-range filter (`cloud.edge_jump_m` 3 mm, removes flying pixels), back-projected to the base frame, voxel `cloud.voxel_m` 0.8 mm, outlier removal (`outlier_radius_m` 3 mm, `outlier_min_nb` 4).
5. Per-view COLOUR MARKER cloud: HSV mask (`color_marker.h` 80-105, `s_min` 140, `v_min` 60, 3x3 opening), flying pixels removed on the FULL depth first (`color_marker.edge_jump_m` 4 mm), then the mask is applied, back-projected, voxel 0.5 mm, outlier removal (2 mm, 3 neighbours).
6. Trimmed point-to-point ICP of every view onto the views already merged (25 iterations, keep the best 70 %, max distance 20 mm, on 3 mm voxel copies); the SAME correction is applied to that view's marker cloud. Merged and voxelised. Output `fused_cloud.npy`, `marker_cloud.npy`, `fusion.json` (per-view shift mm / rotation deg).
- Measured: ICP corrections median 4-6 mm, max 10-16 mm; fused 2.2 M points. The merged cloud smears small objects (views disagree by 5-18 mm, table tilt 1.4-6.5 deg per view: see `Code/Calibration`), so the merged scan is used ONLY for the coarse target.

## 3. Coarse target (`/grasp/color_target`) [verified]
- Table plane: RANSAC (800 iterations, `color_marker.table_thresh_m` 3 mm) on a 150 k random subset of the points within +-30 mm of `scan.table_z_m`, refit on the inliers (normal up).
- Object points: inside `workspace.region`, 3-80 mm above that plane, voxel 3 mm, DBSCAN (`cluster_eps_m` 6 mm, `cluster_min_pts` 20). Marker points above the table: DBSCAN (`marker_eps_m` 3 mm, `marker_min_pts` 15). The biggest marker cluster is the head; the target is its MEAN position (x, y, z). Plots and `color_analysis.json` go to `Media/Grasp/work/scans/<ts>/`.
- Marker target: the marker clusters are sorted, but a cluster whose xy extent is larger than `color_marker.marker_max_extent_m` (30 mm) is NOT the sticker (a strip of the same colour on the panel was matched once, 2026-11-10); the target is the largest sticker-sized cluster. In the close view only the marker blob nearest to that target (image-space connected component, >= 30 px) is used by all three grasp modes.
- The merged patch's orientation / normal is NOT used (registration smear). The label strip (also teal) is removed because it lies on the table (below 3 mm).

## 4. View (`/grasp/view`) [verified]
Camera straight over the target at `view_height_m` (0.18 m), home orientation, IK near the start joints (80 deg), joint move, wait 1 s.

## 5. Grasp computation (close view, ONE frame: no registration error between views)
Common first steps (all modes): latest aligned depth + colour; marker pixels -> 3D points; **sticker position/height = MEDIAN of those points** (median because the depth over the glossy head is unreliable and a mean was pulled by stray specks). The approach is always **straight down** (`z_G = (0, 0, -1)`); the jaws close horizontally (`y_G` = jaw axis, `x_G = y_G x z_G`); pre-grasp = TCP + 60 mm up (`grasp.standoff_m`), lift = 80 mm back along the approach (`grasp.lift_m`). Every candidate is expanded into 2 grasps (jaw direction +/-: the same axis, the gripper yawed 180 deg, which matters for reachability only). TCP height = sticker height - `color_marker.grasp_drop_m` (8 mm, a CHOSEN constant, not measured).

### 5.1 `sticker` mode: ARCHIVED 2026-11-10 (`archive/sticker_mode_20261110/`)
The former default: one grasp from the sticker median and the colour outline of the housing around it, no search. Archived because it only works for this sticker and this head (sizes measured around the sticker, not the part's geometry). Two real grasps with it (n = 1 each, 2026-11-07 and 2026-11-10); see the archive README. `housing_footprint` stays in `color_marker.py` for the cloud mode.

### 5.2 `head` mode, the IMAGE method (`/grasp/head_grasp`) [DEFAULT; verified on the arm, n = 1 per run, 4 runs on 2026-11-10]
- Same outline mask, but ONLY those pixels are lifted to 3D with their OWN depth (no flying-pixel filter, `head_band_m` +-60 mm around the sticker height, voxel 0.5 mm, outliers removed): the head cloud. Needs `min_head_points` (200).
- **Grid search (always on, no switch)**, `grid_grasp_search` in `color_marker.py`:
  1. Grid: jaw centres every `grid_m` (1 mm) over the head's xy extent, kept where the head cloud is.
  2. Yaw: only `color_marker.jaw_yaw_offsets_deg` ([0, 90]) relative to the jaw axis at the close-view (= home) wrist orientation, which lies along base y (yaw 85.5 deg): wrist joint 6 at its home value (offset 0), or rotated +-90 deg (the same line, tried as the two jaw flips). For the cable as placed on 2026-11-10, 0 = the narrower side faces and +-90 = the wider faces (user); `wide_face_offset_deg: auto` finds the wider-face offset from the sticker: the sticker is on a wide face of the plug (15.0 x 7.5 mm in the STEP model), so the horizontal direction of the sticker plane's normal is the wide-face jaw direction (needs a plane at least 55 deg from horizontal; the sticker planes in 4 real frames were 71-74 deg); the face term is 0 on that family and 1 on the other (the cloud cannot measure it). A number forces an offset, null measures the wall length in the cloud. Empty `jaw_yaw_offsets_deg` = sweep every `yaw_step_deg` (5 deg) over 180 deg instead. Replaced later by the tag + STEP pose.
  3. Pad window: head points within +-finger_width/2 along a. Gap = 2nd-98th percentile extent along b. The jaw centre must sit within `center_tol_m` (1.5 mm) of the middle of the gap. Opening = gap + 2 x `open_margin_m`, must be <= `max_open_m`. Window needs `min_window_points`.
  4. Contacts: a band of `contact_band_m` (1.5 mm) at each end of the gap, >= 3 points each.
  5. Finger collision: both finger boxes (finger thickness x finger width, from the fingertip up `finger_box_h_m`) may hold at most `max_finger_hits` non-head scene points (`scene_points`: every depth pixel outside the head mask within footprint radius + 25 mm).
  6. Cost = quality terms `w_anti` x (1 - antipodal) + `w_even` x width unevenness + `w_center` x distance to the sticker / 10 mm, plus the three grip terms (each 0 for the best candidate, 1 for the worst; changed 2026-11-10 from a gap-width term): `w_depth` x (1 - extra depth / deepest) deeper, `w_contact` x (1 - contact points / most points) covering more points, `w_face` x face penalty: the pad on the wider face (0 on the `wide_face_offset_deg` family, 1 on the other; if that is null, 1 - wall length along the pad strip / longest, measured from the head cloud's outline, which is unreliable). Antipodal = mean of (outline normal . jaw direction) over the two contact bands. The outline normals are horizontal and outward (min-variance direction of each point's xy neighbourhood, `outline_normals`): the 3D PCA normals on this head follow the depth ramp, not the walls, and scored the best yaw 28 deg off the working one (antipodal 0.41 vs 0.77).
  7. Depth: every geometry is tried at each `extra_depth_m` (3, 4, 5, 6, 7 mm) BELOW the usual TCP height (sticker median height - `grasp_drop_m`); a per-window height is not used (the 3D sticker points ramp 27 mm over 11 mm). The finger boxes reach `finger_clearance_m` (3 mm) below the tip, so the tip must stay that far above scene points such as the panel top; a depth the panel blocks is rejected (the filter acts as the depth limit). Cost adds `w_depth` x (1 - extra / deepest extra): deeper = more wall in the pads, within that limit. Best `max_candidates_kept` (200) go to the execute list, both jaw flips each; all valid ones are plotted.
- Real frame of the working grasp (`Media/Grasp/run_20261107_image_mode_offline_validation/plots_grid_search/`): 268 grid points x 36 yaws = 9648 generated, 2118 valid (7529 dropped because the jaw centre was not in the middle of the head gap; the opening, contact and collision filters removed none on this frame). Best: yaw 105 deg (the working grasp is 102 deg), TCP (256.7, -29.1, -0.4) mm vs (256.6, -28.9, -0.4), gap 12.0 mm, opening 36.0 mm vs 37.4. Offline only, never executed on the arm.

### 5.4 `model` mode: STEP model + ArUco tag on the panel (`/grasp/model_grasp`, `--mode model`) [NEW 2026-11-10, offline-tested, NOT run on the arm]
Separate from the head and cloud modes: they do not use the tag, the model or `config/panel_map.yaml`. Same scan, coarse target, close view and execute.
- **Tag pose** (`housing_grasp/model_mode.py`): ArUco DICT_4X4_50 id 0 (print `tags/panel_tags_aruco4x4_25mm.pdf`, stick it flat on the panel top 30-50 mm from the plug), sub-pixel corners, `solvePnPGeneric` (IPPE square, the solution with the tag normal pointing up); x, y, yaw from the tag, the panel height from the depth over the tag area (the tag's scale is only good to ~1 mm in height). Synthetic test: yaw < 1 deg, x, y < 1 mm.
- **Virtual map** (`config/panel_map.yaml`): one entry per plug type with its pose in the tag frame (`xy_m`, `yaw_deg`); only `usb_a` exists (the other two plugs need their models). `null` = not measured: the mode refuses to run. Measure it with `tools/calibrate_panel_map.py --size-m <ruler value> FRAME.npz ... --write` from close frames of normal runs where the tag and the plug's sticker are both visible (the sticker gives the plug's x, y, yaw: plane normal, axis 3.75 mm behind the sticker); the spread over frames at different panel positions tells how good the map is.
- **Candidates** (`housing_grasp/model_grasp.py`, offline): the STEP model standing upright in the panel (housing 0..20 mm above the panel), every jaw yaw / pad position / tip height scored like the head mode (antipodal normals, deeper, more contact points, wider face, centred), stored in `CAD_files/USB_A_Plug_grasp_candidates_top200.json` (plug frame, best first: pads on the 15 x 20 mm wide faces, gap 7.5 mm, tip 3 mm above the panel). At run time they are placed with the plug pose (tip height = panel height + `u0_mm`) and executed in rank order (both jaw flips; first one with a feasible IK chain).
- **Sticker check**: if the sticker is seen, the plug pose from it is compared with the tag-based pose and reported; `verify_tol_m` makes it a stop.
- **Not in it**: no live finger-collision test (the tip is above the panel by construction; the cable and other objects are not checked), no lean of the plug (assumed upright), no second and third plug.
- **Needed before the first run**: the printed tag stuck on the panel, its measured size, the calibrated plug offset.

### 5.5 `cad` mode: STEP model fitted to 3 close views (`/grasp/cad_scan` + `/grasp/cad_grasp`, `--mode cad`) [NEW 2026-11-18, offline-tested on synthetic and on 3 real 3-view jack/USB scans, NOT run on the arm]
Replaces the 7-pose scan and the merged cloud: `cad_scan` finds the sticker, moves to 3 close tilted views, `cad_grasp` fits the connector's STEP model and places its grasp candidates. Head, cloud and model modes are untouched. Why it exists: Jay's branch (`cad_multiview_grasping`) fits the CAD to 3 NEAR-VERTICAL views from 0.31 m; the audio jack came out tilted 19 deg (cable pulling the fit, views that cannot see tilt), and no candidate had a reachable path. This mode changes that:
- **Connectors**: everything per connector is in `config/connectors.yaml` (STEP/mesh, model frame, panel seat height, fit range, contact range, symmetry, segmentation radius). New connector = STEP file + a YAML entry + `python3 tools/make_candidates.py NAME`. USB-A (`usb_a`) and 3.5 mm jack (`micro_jack`) exist. Select with node param `cad_connector` or `active:`.
- **Find** (`cad_scan`): from home the sticker blob (sticker-sized, in the workspace; nearest `cad_hint` 'x,y' if given, else the largest) gives the target; if not seen from home, the 7-pose scan + `color_target` is the fallback.
- **3 views** (`views:`): camera 0.20 m from the target, 35 deg off vertical (a view whose fingertip would be lower than `tip_clear_mm` = 35 mm above the sticker is skipped: the fingertips are 126 mm ahead of the camera), azimuths 0 / 120 / 240 deg (each tried at +-30 / +-60 deg if IK fails), smallest turn from the home orientation, joint moves at `motion.joint_speed_deg_s` (25) with no return home. Tilted views from three sides see the side walls, which is what fixes the plug's tilt.
- **Points per view** (`cad_fit.connector_points`): the sticker blob nearest the target, then dark + sticker pixels connected to it within the connector's `roi_radius_mm`, depth-edge filtered, mm in the base frame. The cable is included and removed by the trimmed fit.
- **Which views** (`tools/scan_observability.py`, expected 1-sigma pose error from the information matrix, perfect camera poses assumed): 3 close views at 35 deg / 0.20 m pin the jack's tilt to 0.2 deg and cover 94% of it; 4 views 0.18 deg; 2 views 0.3 deg but only 74% covered; the home view alone 14 deg (6% covered); Jay's 3 near-vertical views at 0.31 m 4.7 deg (23% covered). The 7 recorded poses are as good on paper (0.2 deg) but their camera poses disagree by ~19 mm (below), so the close views (small neighbourhood, shared errors) are the ones to trust; `views.coarse` = never / fallback / always sets whether the 7-pose scan runs.
- **Panel plane** (`cad_fit.panel_plane`): white pixels 16-40 mm around the connector, RANSAC over near-horizontal planes (<= 6 deg) that cross the plug axis 0-25 mm below its lowest seen point (the white plate and tape cannot win). It fixes the plug axis (= panel normal) and height.
- **Fit** (`cad_fit.fit_pose`): observed-to-model trimmed robust distance (best 70% of the points, soft-L1), multi-start yaw (one start for the axially symmetric jack). Two models: seated on the panel (4 DOF) and free tilt <= 15 deg; the free-tilt fit is used only if its held-out error is 25% better (a leaning plug is measured, not assumed away).
- **Gate** (`fit.gate`): leave-one-VIEW-out (fit on 2 views, test on the 3rd): p80 <= 3 mm and >= 70% of the held-out points within 2 mm; the leave-one-out poses agree (position 3 mm, axis 5 deg); the fitted axis crosses the measured panel plane within 3 mm of the connector's seat height (catches a bad plane or the wrong connector). A rejected fit stops before any grasp (`fit.gate.require`), with the evidence saved.
- **Candidates** (`tools/make_candidates.py`, offline): the same model-frame search as the model mode (`model_grasp.search`) on the contact part of the model, tip height from the seat + 3 mm. Placed with the full fitted pose; the approach follows the plug axis (`_grasps_from` takes an `approach`); the lift is along it. Round connectors: the jaw yaws are `place.jaw_yaw_offsets_deg` ([0, 90]) from the home jaw axis, like the head mode.
- **Live filters** (`cad_place.place`): fingertip >= 3 mm above the measured panel plane; finger boxes vs the scene points the model does not explain (<= 8 hits). Then `/grasp/execute` as for every mode (IK chain in rank order, opening set at the pre-grasp pose, hold check).
- **Real-data check (2026-11-18, Jay's 3-view jack scan from 0.31 m, near-vertical, i.e. the worst case)**: panel plane found (2.6 deg), plug seated, tilt 0 deg (his fit: 19 deg), implied seat height 2.2 mm in both jack runs vs the 2.1 mm assumed from the STEP, held-out within 2 mm 75/69/85% (gate 70%: rejected by 1 point in 100, as designed), 13 of 18 candidates survive. USB scene with the plug at the panel end: panel plane bad, implied seat -14 mm, gate rejects.
- **Several cables** (`run_pipeline.py --mode cad --connector usb_a micro_jack [--hint X,Y X,Y] [--between pause|release|stop]`; logic in `ros2_iface/pipeline.py`, tested with fakes in `tests/test_pipeline.py`): each connector in its own sub-folder `NN_name/` of the run folder plus a `summary.json`; the node gets `cad_connector` / `cad_hint` before each cable. Every cable starts with the arm home and the gripper open, so between two cables that was picked up the gripper is NOT opened by the start check on its own: `pause` (default) asks the operator to take the cable and press Enter, `release` opens at once (the cable drops), `stop` ends the run. A cable that was not picked up (fit rejected, no candidate) does not block the next; a failed execute stops the run. One sticker per cable: give each connector its own marker colour in `connectors.yaml` (`marker:`) or a `--hint` with its approximate x,y, otherwise the largest sticker in view is taken. The run's files are collected by remembering which node outputs existed before the cable started, never by timestamp, so an earlier cable's plan can not end up in the next folder. Exit status 0 only if every cable was planned (or picked with `--grasp`).
- **Plans**: `execute` tries every grasp of a CAD plan (all candidates x both jaw flips, not only 4) and a plan is single use once the arm moves; `cad_scan` / `cad_grasp` clear the previous plan first and `cad_grasp` refuses views taken of another connector.
- **Not yet shown**: reachability of the 3 view poses and the grasps on the arm, the time of the 3 views (estimate 10-15 s vs 85 s), the fit with the NEW close views (only far near-vertical real views were available), any grasp. The jack's seat height is assumed (the data agree). The panel plane needs the white panel in view.

### 5.3 `cloud` mode (`/grasp/cloud_grasp`): marker region only [offline]
- The black body is not used (unless `extent_source: footprint`). Marker points further than `footprint_radius_m` from the median (stray specks) are dropped.
- Sticker rectangle from the IMAGE: min-area rectangle of the marker blob at the sticker; its 4 corners are intersected with the horizontal plane `z = sticker height`. This gives two edge directions (long, short), their lengths, and the centre. (The 3D sticker points are not used for axes: their plane comes out tilted 73 deg although the image shows a flat sticker facing up.)
- **Candidate search (`candidate_search: true`)**: families = jaws along the LONG edge or along the SHORT edge (pads then touch the faces perpendicular to the jaw; `face_width_m` = the other extent) x yaw offsets `yaw_steps_deg` (-10, 0, +10) x `n_offsets` (5) pad positions across the sticker (within +-min(`offset_span_m`, extent/2 - finger_width/2)) x 2 flips. Opening = extent along the jaw + 2 margins (rejected if over `gripper.max_open_m`). Cost = family prior (0 for the preferred family, 0.5 for the other) + 0.3 x centring + `yaw_penalty` (0.3) x |yaw| / 45. Typically 30 candidates x 2 flips.
- **Search OFF**: ONE candidate = preferred family, yaw 0, centred (the top of the searched list).
- Preferred family: `contact_faces: edge_prior` -> `jaw_edge`; `larger` -> jaw along the SHORTER extent (pads on the wider faces); `smaller` -> the opposite. **The extents come from `extent_source`**: from the sticker (marker only) or from the head outline.
- **Important, measured on the real head**: the sticker's proportions are OPPOSITE to the head's (sticker long edge 12.5 mm lies ACROSS the head, whose long axis 24.7 mm runs along the cable). So `larger` + `sticker` extents picks the jaw 79 deg off (along the cable); `larger` + `footprint` picks 0 deg off (the grasp that worked); `edge_prior` with `jaw_edge: long` is 11 deg off (covered by the +-10 deg yaw candidates). Marker data alone cannot tell which edge is right; `jaw_edge` is a convention for how the sticker is applied.

### 5.4 Which faces the pads touch
Straight-down approach: the jaws can only close across the head seen from above, so the pads always touch SIDE faces, never the top (sticker) or bottom (rests in the slot) faces. The working grasp (jaw across the 13.4 mm dimension) touched the two long side faces (24.7 mm wide), the larger-area pair that is reachable. Touching the wide faces would need a side approach: not built.

## 6. Execute (`/grasp/execute`) [verified on the arm, n = 1]
1. Candidates are tried in rank order, at most `max_candidates` (4) grasps: for each, `plan_chain` checks pre-grasp IK near the current joints (`grasp.max_joint_dev_deg` 120), the straight descent and the straight lift (MoveIt line paths, joint-jump check, table floor). The first feasible one is used (in the working run the first flip had no near IK and the second was used).
2. Unless `dry_run:=false` AND `/grasp/allow_grasp` were called, it stops here ("NOT EXECUTED, motion checked only").
3. If the gripper was left part-closed, open it fully first (opening only). Joint move to the pre-grasp pose (`grasp.standoff_m` 60 mm above the grasp) with the gripper as it is. THEN, at the pre-grasp pose and just before the descent, set the jaw opening (table `gripper.position_to_width_m` from `/grasp/scan_gripper`), ramp rate 0.3. Straight descent to the TCP target. (Until 2026-11-10 the opening was set at the start, before the long move to the pre-grasp, so the gripper narrowed early.)
4. Close: smooth ramp to `gripper.close_cmd` (0.81 rad) at rate 0.2, effort 30. While closing, after 15 % of the ramp, if the fingers lag the command by more than 0.05 (fraction of full) for 3 consecutive 40 ms steps = contact: squeeze +0.04 and hold 0.5 s. `held` (finger check) = contact or final position below `empty_frac` x close_cmd (0.790).
5. Lift 80 mm along the retreat direction.
6. Wrist-camera hold check after the lift (HW7 rule): median of 3 depth frames; depth between the fingertips (rows 400-480, cols 340-510) below `hold_check.tip_max_m` (0.20 m) AND the table in the lower corners (rows 320-480, cols 0-255 and 595-848) at least `margin_m` (0.08 m) farther. Success = finger check OR camera check [camera check: **not run** on a held object yet; the finger check alone gave a false "empty" on the working grasp: thin objects read ~1.0].
7. The object stays held, lifted; nothing releases it.

## 7. Data collected
`run_pipeline.py RUN_DIR --grasp [--skip-scan] [--mode ...]`: records camera video + joints/gripper/tool pose at 10 Hz (`record.py`), stage logs and results (`controller.log`, `metrics.json`), copies the scan and the plan folders and plots. `export_evidence.py RUN_DIR`: PLY point clouds, perception overlays, annotated video. Layout rules: `../../Media/RULES.md`; runs live in `../../Media/Grasp/`.

## 8. What is switched off / assumed (read before trusting a run)
- Finger-volume collision check and the optimizer limits: removed with the archived depth planner; nothing checks fingers against the panel, bolts, post or cable. Table floor only.
- The 8 mm drop, the 12 mm margin per side, the `jaw_edge: long` convention and the +-10 deg yaw steps are chosen values.
- Needs a TEAL sticker on the head's top face, visible from above; a bigger teal object in the workspace would be picked instead. The head must be inside `workspace.region` and the close view reachable by IK.
- Not run on the arm: `head` and `cloud` modes, the hold check, `/grasp/pick` as one call, repeats (n >= 10).
- `color_marker.normal_knn`, `max_nz`, `min_plane_points` and `color_marker.marker_planes()` belong to the earlier two-plane idea and are not used by any mode.
